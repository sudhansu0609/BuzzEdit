# Audio Suite — Audition-style audio effects in BuzzEdit (plan, 2026-10-09)

**Status: plan written 2026-10-09, implementation starting the same day.** Update the Status column in §4 after every item.

The creator's ask (2026-10-09): sound/audio actions in BuzzEdit like Adobe Audition — filter and EQ
options like Audition's, amplitude and compression, pitch and voice change, detect noise and remove
noise the Audition way (noise print → reduction), vocal enhancers.

Honest framing: the engines are FFmpeg's audio filters plus Python DSP and two speech models, not
Adobe's code. The *controls* (names, ranges, presets, the noise-print workflow) can mirror Audition
one for one; the *sound* of each algorithm is ours. §3 marks every effect exact / approximate / not
covered.

## 2. Design

### 2.1 Three racks and one process lane (Audition's Multitrack + Waveform editor)

| Scope | Where it lives | Compiles to |
|---|---|---|
| **Programme (A1) rack** | `Timeline.audio_racks["A1"]: List[AudioEffect]` (new); today's `AudioMaster` voice fields become a preset that *writes* this rack, so old projects still compile | the A1 chain in `compiler.py` (replaces `build_voice_chain` output when a rack exists); range effects carry `start_s/end_s` in programme time → `enable='between(t,a,b)'` |
| **Clip rack** (A2, A3… items, detached audio, music, SFX) | `TimelineItem.audio_effects: List[AudioEffect]` | the item's own filter path before the mix |
| **Master rack** | `Timeline.audio_racks["MASTER"]` | after `amix`, before/instead of today's loudness stage |
| **Processes** (Audition's "(process)" effects: noise reduction with a print, DeepFilterNet, AI enhance, stretch/pitch, voice change, normalize, declip) | run as a job → `data/projects/<id>/audio/versions/<n>_<effect>.wav`; the source gets `audio_override` (path) and `audio_history` (stack) so Undo pops a version; the original file is never touched | the compiler reads `audio_override` for that source |

`AudioEffect = {id, effect: str, params: dict, enabled: bool, start_s?: float, end_s?: float, preset?: str}`.

### 2.2 The effect catalogue is data, the UI is generated from it

`backend/audio/catalogue.py`: one entry per effect — `id`, Audition name, category, `engine`
("ffmpeg" | "process"), `params` (key, label, type number/choice/bool/curve, min, max, step, default,
unit), `presets` (Audition's shipped names where they exist: "Vocal Enhancer: Male/Female", "Podcast
Voice", "Heavy Reduction", "Light Reduction", "Broadcast Limiter", …), and a `compile(params) ->
List[str]` (ffmpeg) or a `process(wav_in, wav_out, params, progress)`. `GET /api/audio/effects`
serves it; the panel renders sliders, dropdowns and curve editors from it, so adding an effect is one
entry plus tests. User presets: `data/audio_presets.json` (`POST/DELETE /api/audio/presets`).

### 2.3 Live preview — play and turn the knob, like Audition

The creator's rule (2026-10-09): effects are heard **live while a knob moves**, not through short
rendered previews. One DSP engine for both: the preview *is* the render graph, so what is heard is
what the render will contain.

- `backend/audio/live.py`: a **live session** per open panel = one persistent ffmpeg process:
  `-ss <playhead> -i <source> -filter_complex "<rack chain of named instances>,azmq" -f s16le -ar 48000 -ac 2 pipe:1`.
  The backend reads the pipe in 4 KiB pieces only when the player asks for more (credits), so ffmpeg
  blocks on the pipe whenever it runs ahead: the audio in flight is never more than ~150 ms old.
- `WS /api/audio/{project}/live`: binary frames carry PCM to the app; JSON frames carry
  `{play, pause, seek, loop:[a,b], set:{effect_id, param, value}, bypass:{effect_id, on}, rack:[...]}`.
  The app plays the PCM through an `AudioWorklet` ring buffer (~100 ms) and sends credits back.
- Every rack effect compiles to **named filter instances** (`equalizer@fx3_0=...`), and the catalogue
  records per parameter whether the ffmpeg option takes a live command (its `T` flag). Live parameters
  reach the running graph through `azmq` (`pyzmq`, BSD) as `fx3_0 gain 2.5` and are heard within
  ~150–250 ms. Measured 2026-10-09: live for `volume`, every `equalizer`/shelf/`highpass`/`lowpass`/
  `bandpass`/`bandreject`/`biquad` option, `firequalizer` gain curves (graphic EQ and FFT Filter),
  `acompressor`, `agate`, `alimiter`, `adynamicequalizer` (de-esser), `dynaudnorm`, `speechnorm`,
  `afftdn`, `arnndn`, `anlmdn`, `rubberband` tempo/pitch, `afir` dry/wet, `asoftclip`, `acrusher`,
  `aexciter`, `stereotools`, `extrastereo`, `aphaseshift`, `adelay`. Parameters without live support
  (`pan`, `anequalizer` except its `change` command, `compand`, `mcompand`, `acrossover`, `deesser`,
  `loudnorm`, `adeclick`/`adeclip`, `aecho`, `chorus`/`flanger`/`aphaser`, `tremolo`, `ladspa`
  controls, an `afir` IR change, `asetrate`) **restart** the ffmpeg process at the playhead, debounced
  120 ms, with a 20 ms fade so the restart is a tick, not a click.
- Bypass per effect: the generic `enable` command for timeline-capable filters, `mix=0` for
  `acompressor`/`arnndn`, a flat `gain_entry` for `firequalizer`, restart for the rest. A/B = bypass all.
- Meters come from the same stream: the app computes peak/RMS from the PCM it plays and K-weighted
  momentary/short-term loudness (ITU-R BS.1770) for the Loudness-Radar readout; integrated LUFS, LRA
  and true peak for a range come from `ebur128` in `analyze`.
- Process effects that cannot stream (Enhance Speech (AI), Voice Conversion, `noisereduce`) keep a
  **Preview** button that renders the selected range and plays it, exactly like Audition's process
  dialogs; DeepFilterNet is a **process**, not a live path: measured 2026-10-09, its LADSPA plugin runs at 1.4× real time on this machine (cannot stream), while the exe runs at 0.08× real time (10 s in 0.8 s), so its Preview is near-instant;
  RNNoise and `afftdn` noise reduction with a captured print are fully live.
- `POST /api/audio/{project}/preview {scope, source_id?, start_s, seconds, rack}` stays for process
  effects and for the Studio (renders the range through the rack to a WAV, < 3 s for 20 s).
- `POST /api/audio/{project}/analyze {source_id, start_s, end_s}` → `astats` (peak, RMS, DC, noise
  floor), `ebur128` (I, LRA, true peak, momentary/short-term series for a Loudness-Radar readout),
  `showspectrumpic` PNG, and a numpy mean-dB spectrum of the range (the noise-print curve).
- **Detect noise**: candidate = the quietest ≥ 0.8 s window inside the transcript's non-speech gaps
  (`asr/vad.py` + word timings), returned as a range the user can drag on the waveform; **Capture
  Noise Print** stores `{range, spectrum}` on the project; the panel shows the curve like Audition's
  Noise Reduction window; **Output noise only** uses `afftdn=om=noise` / the gate's residual so the
  user can hear what is being removed.

### 2.6 Interfaces — the contracts between briefs (A1a, A1b, L, A2, A3, A4 build against these)

**Schema** (`timeline/schema.py`, brief A1a):

```python
class AudioEffect(BaseModel):
    id: str                          # unique in the project, e.g. "fx_7f3a"; also the ffmpeg instance stem
    effect: str                      # catalogue id, e.g. "parametric_eq"
    params: Dict[str, Any] = {}      # UI-unit values keyed by the catalogue's param keys; missing = default
    enabled: bool = True
    start_s: Optional[float] = None  # window inside the scope (programme time for A1/MASTER, clip time for items)
    end_s: Optional[float] = None
    preset: Optional[str] = None

Timeline.audio_racks: Dict[str, List[AudioEffect]]   # keys "A1", "A2", … (track racks) and "MASTER"
TimelineItem.audio_effects: List[AudioEffect]        # clip rack (A2+ items, detached audio; A1 items are rebuilt → ignored)
SourceFile.audio_override: Optional[str]             # processed WAV that replaces this source's audio everywhere
SourceFile.audio_history: List[Dict[str, Any]]       # [{path, effect, params, created}] newest last; Undo pops
```

**Catalogue + compile** (`audio/catalogue.py`, `audio/compile.py`, brief A1b):

```python
ParamDef  = {key, label, type: "number"|"choice"|"bool"|"curve"|"bands", min, max, step, default, unit,
             choices?: [..], live: bool}          # live = every ffmpeg option it drives has the T flag
EffectDef = {id, name (Audition's), category, engine: "ffmpeg"|"process", description,
             params: [ParamDef], presets: {name: {param: value}}, windowable: bool}
EFFECTS: Dict[str, EffectDef]                     # order = menu order of §3
CATEGORIES: List[str]                             # Audition's menu names in order

@dataclass
class CommandSpec:   target: str; option: str; transform: Callable[[Any, Dict[str, Any]], str]
                     # target = "<filter>@<effect.id>_<k>"; transform(value, all_params) -> option value string
@dataclass
class CompiledEffect: effect_id: str; filters: List[str]; commands: Dict[str, List[CommandSpec]];
                     bypass: Literal["enable", "mix", "flat", "restart"]; warnings: List[str]
@dataclass
class CompiledRack:  filters: List[str]; chain: str; effects: List[CompiledEffect];
                     live_params: Dict[Tuple[str, str], List[CommandSpec]]; restart_params: Set[Tuple[str, str]]

def compile_effect(effect: AudioEffect) -> CompiledEffect      # engine "ffmpeg" only; names every instance
def compile_rack(effects: List[AudioEffect], *, scope: str) -> CompiledRack   # skips disabled effects
def commands_for(rack: CompiledRack, effect_id: str, param: str, value: Any,
                 params: Dict[str, Any]) -> Optional[List[Tuple[str, str, str]]]   # None → restart needed
def public_catalogue() -> Dict[str, Any]                       # JSON-safe EFFECTS (no callables)
```
Instances are named `<filter>@<effect.id>_<k>` (`equalizer@fx_7f3a_0`). A window (`start_s/end_s`)
becomes `:enable='between(t,A,B)'` on every timeline-capable filter of the effect; an effect whose
filters are not all timeline-capable has `windowable = False` and compiles to the whole scope with a
warning. `bypass` = "enable" when all filters are timeline-capable, "mix" for `acompressor`/`arnndn`
(mix → 0), "flat" for `firequalizer` (flat `gain_entry`), else "restart".

**Routes** (`routes/audio.py`, prefix `/api/audio`, brief A1a; the live socket is brief L):

| Route | Body → result |
|---|---|
| `GET /effects` | `{effects: [...public_catalogue()], categories: [...]}` |
| `GET /presets`, `POST /presets {effect, name, params}`, `DELETE /presets/{effect}/{name}` | user presets in `data/audio_presets.json` |
| `GET /{project}/racks` | `{racks: {A1: [...], MASTER: [...]}, items: {item_id: [...]}, sources: {source_id: {audio_override, history_len}}}` |
| `PUT /{project}/rack {scope, effects}` | `scope` = `"A1"`, `"MASTER"`, `"A2"`… or `"item:<id>"`; replaces that rack, `revision += 1`, returns the rack |
| `POST /{project}/preview {scope, source_id?, start_s, seconds, effects?}` | renders the range through the rack (plus the voice chain for A1) to `audio/preview_<scope>.wav`; `{path, seconds}` |
| `WS /{project}/live` | brief L, protocol below |

**Compiler integration** (`render/compiler.py`, brief A1a): the A1 rack's chain is appended **after**
`build_voice_chain(master_a)` (both apply; a creator who wants only the rack sets the voice preset
off); an item's `audio_effects` chain is inserted in that item's audio path before its volume/fades;
the MASTER rack goes after `amix` and before the loudness stage. A source with `audio_override` is
read from that WAV instead of its own audio, in every path (render, preview, live).

**Live protocol** (brief L): client → server JSON `{"type":"play"}`, `{"type":"pause"}`,
`{"type":"seek","t":12.3}`, `{"type":"loop","a":1.0,"b":4.5}` / `{"type":"loop","off":true}`,
`{"type":"set","effect_id":"fx_7f3a","param":"gain","value":2.5}`, `{"type":"bypass","effect_id":"fx_7f3a","on":true}`,
`{"type":"rack","effects":[...]}` (replace → restart at the playhead), `{"type":"credits","frames":4800}`.
Server → client: binary frames = interleaved s16le stereo 48 kHz PCM; JSON `{"type":"state","playing":true,"t":12.3}`
every ~250 ms, `{"type":"restarted","t":..}`, `{"type":"ended"}`, `{"type":"error","message":".."}`.
The server never sends more PCM than the client's outstanding credits.

## 6. Implementation notes for whoever picks this up

**Known issues (2026-10-09, open):** Pitch Shifter's "Octave Up" preset ends 79 ms short and the Pitch Bender's audio lands 13–18 ms off after a bend (Rubber Band's latency changes with the ratio; `pitchq` modes differ) — measure `pitchq=quality` vs `speed`, or pad with `apad` + `atrim` to the input length. `firequalizer` appends 2×`delay` of tail (100 ms at delay 0.05); the EQ fix brief checks the render bounds audio to the picture. The firequalizer `scale=loglog` form never applied the curve at the entry frequencies — graphic EQs are biquad cascades since the fix, the FFT Filter uses `scale=linlog` with `cubic_interpolate(f)` and `min_phase=1`.

- Model/IR paths inside filter strings need the escaping in `render/audio.py::_ffmpeg_filter_path`
  (a bare `B:/…` breaks `arnndn=m=`; the same holds for `ladspa=file=` and `afir`'s input).
- `afftdn` noise-print capture is a *command*: `asendcmd=c='0.0 afftdn sn start; 1.2 afftdn sn stop',afftdn=…`
  with the print range first in the stream, or extract the range to a WAV and use `noisereduce`.
- A1 effects attach to programme-time ranges or the A1 rack, never to an A1 item id (items are rebuilt).
- Processes write a new version file and never overwrite; the compiler reads `audio_override`;
  Undo pops `audio_history`. Keep versions under the project so Studio's project copy carries them.
- GPU work (DeepFilterNet exe is CPU-fast; Enhance Speech is GPU) must follow the eject → run →
  offload pattern of `routes/music.py`, and must refuse to start while a render or production is running.
- Keep today's `voice_preset` names working: `master_for_preset` maps a preset to a rack.
- Tests: compile every catalogue entry through `ffmpeg -f lavfi -i anullsrc=r=48000:cl=mono -t 1 -af <chain> -f null -`;
  measurements via `astats`/`ebur128` on synthetic signals (tone + white noise), never on the creator's files in CI.
